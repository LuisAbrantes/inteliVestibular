Cenário Real Inteli

🏢 LogStream (Motor de Busca de Logs em Alta Escala) | Otimização de Índices e Pior Caso em Arquivos de 500k Registros

A LogStream processa registros de auditoria ordenados cronologicamente. Em uma atualização crítica de arquitetura, o time substituiu um mecanismo de busca linear por Busca Binária em uma base com N = 524.288 registros ordenados sem duplicatas. Paralelamente, para ordenar lotes de auditoria em memória, uma rotina legada de Selection Sort executa comparações sucessivas entre elementos para posicionar o menor item a cada passagem. A diretoria técnica solicitou a comprovação matemática do número exato de comparações no pior caso de cada algoritmo.

Núcleo Conceitual

O vestibular do Inteli não exige saber sintaxe de Python ou Java, mas exige saber rastrear a lógica de execução passo a passo: identificar quantas vezes um laço de repetição (for/while) itera e somar progressões aritméticas ou geométricas.

Busca Binária e Escala Logarítmica

A cada comparação no meio da lista ordenada, metade dos elementos é descartada. O número de divisões necessárias para reduzir N a 1 elemento no pior caso é dado por k = ⌈log₂(N)⌉.

Nota lateral: Lembre-se das potências de 2: 2¹⁰ = 1.024, 2¹⁹ = 524.288, 2²⁰ ≈ 1 milhão.

Soma de Gauss em Laços Aninhados

Algoritmos de ordenação por comparação simples (como Selection Sort) realizam (N-1) comparações na 1ª passagem, (N-2) na 2ª, ..., até 1 comparação na última, totalizando uma Progressão Aritmética.

Nota lateral: Soma da PA: S_n = [n × (n + 1)] / 2. Isso gera complexidade quadrática O(N²).
📌 Fórmulas Computacionais Essenciais
Pior caso da Busca Binária: p_b = log₂(N)
Soma de Gauss (1 a n): S_n = n(n + 1) / 2
Potência Binária Chave: 2¹⁰ = 1.024; 2¹⁹ = 524.288; 2²⁰ = 1.048.576
💡 Dica de Ouro: Se N = 524.288, não tente dividir por 2 repetidamente no rascunho: fatore usando potências conhecidas: 524.288 = 1.024 × 512 = 2¹⁰ × 2⁹ = 2¹⁹.

⚠️ Armadilha do "Off-by-One" em Laços

Contar o número de comparações esquecendo se o loop vai de 1 até n-1 ou de 1 até n. Para 10 elementos, o Selection Sort faz 9 + 8 + ... + 1 = 45 comparações, e não 10 + 9 + ... + 1 = 55.

Questão 1 de 2

(Vestibular Inteli 2022.1 - Questão 03) Uma empresa de telecomunicações atualizou seu algoritmo de busca em um banco de dados ordenado alfabeticamente contendo exatamente N = 524.288 usuários. Em vez de busca sequencial, o novo sistema emprega busca binária, dividindo a base pela metade a cada etapa. Quantas comparações, no máximo (pior caso), esse algoritmo realizará para localizar um usuário ou concluir que ele não existe no banco?

🔍 Resolução Oficial Comentada
Resolução Passo a Passo:
1. A fórmula do número de passos da busca binária no pior caso é p_b = log₂(N).
2. Temos N = 524.288.
3. Decompomos em potências conhecidas de 2:
2¹⁰ = 1.024
2¹⁹ = 2¹⁰ × 2⁹ = 1.024 × 512 = 524.288.
4. Portanto, p_b = log₂(2¹⁹) = 19.
5. No pior cenário possível, são necessárias apenas 19 comparações para encontrar qualquer registro entre mais de meio milhão de usuários.
Questão 2 de 2

(Vestibular Inteli 2023 - Questão 17) Para ordenar um array desordenado contendo n = 10 elementos distintos através do algoritmo Selection Sort, o programa compara o 1º elemento com os outros 9 para selecionar o menor (9 comparações). Em seguida, compara o 2º com os outros 8 (8 comparações), e assim por diante até restar 1 elemento (1 comparação). Qual é o número total de operações de comparação realizadas?

🔍 Resolução Oficial Comentada
Resolução Passo a Passo:
1. O número de operações de comparação é a sequência decrescente: 9 + 8 + 7 + 6 + 5 + 4 + 3 + 2 + 1.
2. Trata-se de uma Progressão Aritmética de 9 termos com primeiro termo 1 e último termo 9.
3. Pela fórmula de Gauss: S = (n × (n + 1)) / 2 onde n = 9.
4. S = (9 × 10) / 2 = 90 / 2 = 45 comparações.
