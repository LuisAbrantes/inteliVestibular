Cenário Real Inteli

🏢 CloudMesh (Orquestradora de Clusters Multi-Cloud) | Auditoria de Latência e SLAs em AWS, GCP e Azure

A CloudMesh roteia requisições de pagamentos digitais entre três datacenters em nuvem:

  • Cluster AWS (São Paulo): processou 50.000 requisições com latência média de 40 ms.
  • Cluster GCP (Santiago): processou 30.000 requisições com latência média de 60 ms.
  • Cluster Azure (Virgínia): processou 20.000 requisições com latência média de 120 ms.
A auditoria externa exige a comprovação da latência média global ponderada do sistema e uma análise da mediana para garantir que os SLAs contratuais de 50 ms não foram violados por distorções de outliers.

Núcleo Conceitual

Em estatística no Inteli, médias simples de grupos com volumes desiguais são terminantemente incorretas: é obrigatório ponderar pelo peso ou frequência amostral. Além disso, o candidato deve dominar a robustez da mediana frente a distribuições assimétricas.

Média Aritmética Ponderada

Soma dos produtos de cada valor pelo seu respectivo peso (ou volume de requisições), dividida pela soma total dos pesos: Σ(x_i × w_i) / Σw_i.

Nota lateral: Simplifique os pesos antes de multiplicar! Em vez de 50k, 30k e 20k, use 5, 3 e 2.

Mediana vs Média em Sistemas de TI

A mediana é o valor central que divide a amostra ordenada em duas metades de 50%. Ao contrário da média, ela não é distorcida por requisições pontuais muito lentas (outliers de timeout).

Nota lateral: Na indústria de software, p50 é a mediana, e p95/p99 são percentis de cauda longa.
📌 Estatística para Benchmark Tech
Média Ponderada: x̄ = (w₁x₁ + w₂x₂ + ... + wₙxₙ) / (w₁ + w₂ + ... + wₙ)
Mediana (n ímpar): Posição = (n + 1) / 2
Mediana (n par): Média aritmética dos elementos centrais nas posições n/2 e (n/2) + 1
💡 Dica de Ouro: Para calcular média ponderada rapidamente, divida todos os pesos pelo seu máximo divisor comum antes de efetuar as multiplicações.

⚠️ Armadilha da Média das Médias

Calcular a média simples das latências (40 + 60 + 120) / 3 = 73,3 ms sem ponderar pelo número de requisições. O cluster da AWS processou metade de todo o tráfego a 40 ms, puxando a média real para bem mais baixo!

Questão 1 de 2

Qual foi a latência média global ponderada real das 100.000 requisições processadas pela CloudMesh?

🔍 Resolução Oficial Comentada
Resolução Passo a Passo:
1. Identificamos os volumes de requisições (pesos): w_1 = 50.000, w_2 = 30.000, w_3 = 20.000.
2. Volume total: W = 50.000 + 30.000 + 20.000 = 100.000.
3. Simplificamos dividindo todos os pesos por 10.000: w'_1 = 5, w'_2 = 3, w'_3 = 2 (soma = 10).
4. Aplicamos a fórmula da média ponderada:
x̄ = (5 × 40 + 3 × 60 + 2 × 120) / 10
x̄ = (200 + 180 + 240) / 10 = 620 / 10 = 62,0 ms.
Questão 2 de 2

Uma série temporal de 7 requisições individuais apresentou as seguintes latências em milissegundos: [35, 38, 42, 45, 48, 52, 980]. Se a requisição de 980 ms (um timeout de conexão) for descartada como anomalia, o que ocorrerá respectivamente com a MÉDIA e com a MEDIANA da latência restante?

🔍 Resolução Oficial Comentada
Resolução Passo a Passo:
1. Amostra original (7 elementos ordenados): [35, 38, 42, 45, 48, 52, 980].
- Média original: (35 + 38 + 42 + 45 + 48 + 52 + 980) / 7 = 1.240 / 7 ≈ 177,1 ms.
- Mediana original: elemento central (4ª posição) = 45 ms.
2. Amostra após remoção do outlier (6 elementos): [35, 38, 42, 45, 48, 52].
- Nova média: (35 + 38 + 42 + 45 + 48 + 52) / 6 = 260 / 6 ≈ 43,3 ms (queda expressiva de 177 para 43 ms!).
- Nova mediana: média dos dois centrais (3ª e 4ª posições) = (42 + 45) / 2 = 43,5 ms (variação mínima de apenas 1,5 ms).
3. Isso comprova por que benchmarks de computação em nuvem utilizam a mediana (p50) como métrica robusta de estabilidade.
